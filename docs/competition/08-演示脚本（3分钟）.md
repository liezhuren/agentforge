# 08 · 现场演示脚本（3 分钟）+ 彩排清单

> 演示的第一原则：**不要赌现场网络和新生成的代码**。
> 用已经跑出来的真实产物 + 真实的失败案例，比"现场再生成一个"稳得多。
> 想展示"实时运行"，就把**锚点**当现场主角 —— 它零 LLM、毫秒级、必然成功。

---

## 一、演示目标（只讲一件事）

**"它不只会生成，它会告诉我哪里没做对，而且告诉我是谁的错。"**

3 分钟里不要试图展示"完整的研发流程"，那需要 40 分钟。
要展示的是**失败被抓住的那一瞬间**。

---

## 二、分镜（180 秒）

### 第 0 段（0:00–0:20）开场，不碰电脑

> "我用三个 AI 角色跑了一个真实课题：给科研会议做茶歇系统。
> 它产出了 4,443 行代码、39 条测试。**编译是过的。**
> 现在我先不跑测试，我先让它自己检查一遍 —— 因为它当初就是在这里骗了我。"

**动作**：切换到终端（或 Web 控制台），停在"准备跑锚点"的状态。

---

### 第 1 段（0:20–1:10）跑锚点，抓出"写了没接线"

**命令**（零 LLM、毫秒级、必然成功）：

```bash
node scripts/anchor-benchmark.ts          # 先证明这套检查自己准
```

预期输出（**必须提前验证过**）：

```
样本 45：注入 30 + 干净 15
TP 30  FN 0  FP 0  TN 15  严重度不符 0
全部样本符合期望：无误报、无漏报。
```

> "45 个样本，30 个我故意注入的缺陷，15 个干净对照。
> **零漏报、零误报** —— 这是我敢用它判定的前提。
> 一条会对好代码报警的检查，角色很快就会学会怎么糊弄它。"

**接着跑真实产物的锚点**（用 `workspace/cb-2` 那份真实产物，跑 A7）：

```bash
node scripts/anchor-benchmark.ts --sample A7-09-unwired-handler
```

或直接展示 A7 在 cb-2 上的真实结论（预先生成好的输出，**贴屏展示**）：

```
A7 · FAIL
  endpoint-stub   api/app.ts:205  「not implemented yet」占位，运行期返回 501
  unwired-handler api/papers.ts:370   handlePapersRoute（export-only）
  unwired-handler api/comments.ts:187 handleCommentsRequest（never）
  ...
```

> "这里是最有意思的地方：`handlePapersRoute` 在这个文件里出现了 **5 次** ——
> 定义、两个别名、一个默认导出。**按出现次数判断，它算"接线了"。**
> 但一次都没被调用。所以我们的判据不是次数，是**引用行的性质**。"

---

### 第 2 段（1:10–1:50）说明"为什么会这样"，翻到根因

**展示一行日志**（run-progress 的上下文审计）：

```
上下文：7,052 / 60,000 字符（12%）  注入 1 个·丢弃 0 个  [pm · produce:PRD]
```

> "修之前，这里是 24,000 字符的预算，被三件散文吃掉 95%，
> **契约、代码、测试报告一件都进不去**。
> 它写不出接线，不是因为它不会，是因为它**没见过别的模块**。"

**给出那个签名数字**：

```
输入 token: 10,669 → 10,664   （项目从 0 行长到 4,443 行）
```

> "八次调用，输入波动 42 个 token。项目长了四千行，它的视野**一个字都没变**。
> 这就是我花了二十轮才看出来的东西 —— 而系统里当时**根本没有地方记录这件事**。
> 所以现在我加了一条：**每次调用都记下它看到了什么、丢了什么、为什么丢**。"

---

### 第 3 段（1:50–2:30）展示"真的在跑的系统"

**动作**：浏览器打开生成的应用（如果 cb 轮次产出的能用就用；否则用 `demo-e2e` 的产物）。

演示路径（保持最短）：
1. 打开首页 → 看到论文列表
2. 用一个已有账号登录（**不要现场注册**，避免时间不可控）
3. 发一条评论 → 刷新 → 评论在
4. 回终端跑一次 `npm run typecheck`（快、几乎必过）

> "这是 AI 写的。它的 UI 不漂亮，但它能动。
> 而比它能动更重要的是：**我知道它哪里不能动**。"

**兜底**：如果 UI 打不开，就切到 `npm run test` 的**真实输出**，
展示"13 条过了、26 条失败（501 占位）"——**失败也是好故事**，因为它正好回到第 1 段的主题。

---

### 第 4 段（2:30–3:00）收尾，一句话

> "所以 AgentForge 做的不是'让 AI 写代码'，那件事已经有人在做。
> 我们做的是**让 AI 的产出可以被机械验证** ——
> 11 条锚点、零 LLM 判定、哈希链日志、45 个样本的靶场。
> 因为 AI 编程真正的门槛不是生成，是**你敢不敢把它交付出去**。
> 谢谢。"

## 三、彩排清单（现场前 30 分钟逐项打勾）

### 环境
- [ ] 用**演示专用端口**（建议 8787/8788 已确认空闲）
- [ ] `node --version` ≥ 24（类型剥离需要）
- [ ] **不要在现场 `npm install`** —— 零依赖，不需要装任何东西
- [ ] 关掉会弹通知的软件（截图里出现微信弹窗最扣分）

### 命令
- [ ] `node scripts/anchor-benchmark.ts` 跑通，且 **FP = 0**
- [ ] `node scripts/run-progress.ts workspace/cb-2` 输出正常
- [ ] `npm run typecheck` 跑通（在要演示的那个工作区里）
- [ ] 401/501 的输出**提前截图**：现场只展示截图，不赌实时

### 页面
- [ ] 首页能开（**提前预热浏览器**，避免冷启动白屏）
- [ ] 登录用**已有账号**，密码写在便签上（别现场想）
- [ ] 缩放比例调到 125% 以上，投屏才看得清

### 讲稿
- [ ] 3 分钟内说完（**对着秒表练两遍**）
- [ ] 准备三个"如果被问到"的回答：
  - "为什么不用 LangGraph/CrewAI？" → 它们解决"怎么让 Agent 干活"，我们解决"怎么判断干完了没有、没干完怪谁"
  - "这算 AI 应用还是 AI 基础设施？" → 基础设施，但它产出的是可用应用（有现场产物）
  - "一次跑完一个完整项目了吗？" → **诚实**：还没有；这一轮 4 个并行 run 正在验证

### 心态
- [ ] **不解释超过 20 秒**。被打断就顺着答，然后回到"我展示了什么"
- [ ] 任何一步失败，立刻切到截图，**不现场调试**
