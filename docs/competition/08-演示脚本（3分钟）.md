# 08 · 现场演示脚本（3 分钟）+ 彩排清单

> 演示第一原则：**不赌现场网络、不赌现场再生成**。
> 用一个**已经跑出来并且验证过**的产物（`demo/coffeebreak/`），
> 再当场演示**锚点判定**（零 LLM、毫秒级、必然成功）。
>
> 这比"现场再生成一个"稳一百倍，而且更真实 —— 因为你能说出每个数字的出处。

---

## 一、演示目标（只讲一件事）

**它不只会生成，它会自己检查，而且检查结论可以复核。**

三分钟不讲完整流程（那要 40 分钟），只展示两样东西：
① 一个 AI 写出来**真的能跑**的系统；② 它在生成过程中**自己报过哪些问题**。

---

## 二、分镜（180 秒）

### 第 0 段（0:00–0:15）开场，先给结论

> "这是五个 AI 角色协作做出来的茶歇系统 —— 任务书里 18 项论文属性、注册登录、
> 评论回复、好友关注、兴趣推荐，全都在。
> **22 条测试全过，33 条端到端验收全过。**
> 但我要讲的不是「AI 能写代码」，而是**我怎么确认它真的写对了**。"

**动作**：屏幕上是浏览器里的首页（提前开好）。

---

### 第 1 段（0:15–1:05）跑一遍真实用户旅程

**终端**（提前在另一个窗口 `cd demo/coffeebreak && node src/api/server.ts`）：

```bash
node e2e.mjs
```

预期输出（**提前验证过，33 条全 ✔**）：

```
══════ cb-6 端到端验收（http://127.0.0.1:8788）══════
  ✔ GET /health → 200 且 status=ok  {"status":"ok"}
  ✔ GET / → 200 HTML（界面存在）  29378 字节
  ✔ 注册 → 201
  ✔ 重复用户名 → 409
  ✔ 登录 → 200 且返回 token
  ✔ 管理员创建论文 → 201
  ✔ 详情 18 项属性齐全  18/18          ← 停在这里说一句
  ✔ 普通用户删论文 → 403（权限生效）
  ✔ 对评论回复 → 201
  ✔ 好友请求 / 关注 / 推荐非空 …
结果：通过 33，失败 0
```

**口头强调两句**：
- "`18/18` —— 任务书列的那 18 个论文属性，一条不少地存下来又读回来了。"
- "`403` —— 普通用户删不了论文。这是权限边界，不是运气。"

**动作**：切浏览器，用 `admin/admin123` 建一篇论文、评论、回复（**30 秒内完成，不纠结 UI**）。

---

### 第 2 段（1:05–1:50）真正的差异化：它自己报过什么问题

**切终端**，展示生成过程的 Gate 轨迹（`docs/competition/evidence/cb-6-gates.txt`）：

```
BUILDING  seq1  A1:WARN A2:PASS A3:PASS A4:PASS A5:PASS A7:FAIL A8:PASS B2:FAIL  -> RETRY_ROLE
BUILDING  seq2  A1:WARN A2:PASS A3:PASS A4:PASS A5:PASS A7:WARN A8:PASS B2:PASS  -> ADVANCE
REVIEW    seq1  A1:WARN A2:PASS A3:PASS A4:PASS A5:PASS A6:FAIL A7:WARN A8:PASS B1:SKIPPED B2:PASS B3:SKIPPED -> RETRY_ROLE
```

> "看三件事：
> **第一，`A5:PASS` 说明它真的把测试跑起来了**，不是「写了测试文件就算完成」。
> 第二，同一轮 `A7:FAIL` `B2:FAIL` → **被打回返工**，第二轮才降到 WARN。它没有放过自己。
> 第三，`A6:FAIL` 说的是**服务进程在就绪前退出** —— 那一刻入口文件确实还没写出来。
> **这是真抓到的一个缺口，不是误报。** 修完之后 A6 变成 PASS，`readyMs 624`。"

**再补一句诚实的话**：
> "`B1` 和 `B3` 是 `SKIPPED` —— 语义判定和异议环节没跑完。
> 在我们系统里 **SKIPPED 永远不等于 PASS**，所以我不把它算作通过。"

---

### 第 3 段（1:50–2:25）证明"检查本身可信"

**终端**：

```bash
node scripts/anchor-benchmark.ts
```

```
样本 45：注入 30 + 干净 15
TP 30  FN 0  FP 0  TN 15  严重度不符 0
全部样本符合期望：无误报、无漏报。
```

> "45 个样本，30 个我故意注入的缺陷、15 个干净对照。
> **零漏报、零误报。**
> 为什么要证明这个？因为一条会对好代码报警的检查，角色很快就会学会怎么糊弄它 ——
> 此后它所有的真报都不值钱了。"

---

### 第 4 段（2:25–3:00）收尾，把"不完美"也说掉

> "最后说我这一轮**没做到**的：
> 它没有一次自主跑到最终交付 —— 成功那一轮在最后一道关卡之后，进程被运行环境回收了。
> 四轮并行只成了一轮，方差还很大。
> 但我想强调的是：**每一轮的判定都被记录下来了，可以被复核。**
> 从「AI 说它做完了」到「我能证明它做完了」，中间缺的正是这些东西。
> 谢谢。"

## 三、彩排清单（现场前 30 分钟逐项打勾）

### 环境
- [ ] Node ≥ 24（`node --version`）
- [ ] **不需要 `npm install`** —— 零第三方依赖，这是设计的一部分
- [ ] 端口 8788 空闲：`Get-NetTCPConnection -State Listen -LocalPort 8788`
- [ ] 关掉会弹通知的软件

### 必跑的四个命令（全部提前跑通，并记住输出）
- [ ] `cd demo/coffeebreak && node src/api/server.ts` → `listening on 8788`
- [ ] `node run-tests.mjs` → **22 / 22**
- [ ] `node e2e.mjs` → **33 / 33**
- [ ] `node scripts/anchor-benchmark.ts` → **TP 30 / FN 0 / FP 0 / TN 15**

### 页面
- [ ] 浏览器预热，首页 29KB 秒开
- [ ] 登录用 `admin` / `admin123`（**别现场注册**）
- [ ] 缩放 125%+，投屏看得清

### 讲稿
- [ ] 3 分钟对着秒表练两遍
- [ ] 准备好三个回答：
  - "为什么不自己写？" → 它不是替代人写代码，是让 AI 的产出**可以被验证**
  - "为什么不用 LangGraph/CrewAI？" → 它们解决"怎么让 Agent 干活"，我们解决"怎么判断干完了没有、没干完怪谁"
  - "一次能跑完吗？" → **诚实**：还没有；四轮并行只成一，产品可用但方差大

### 心态
- [ ] 任何一步失败，**立刻切截图**，不现场调试
- [ ] 不解释超过 20 秒

## 四、如果只有 60 秒

```bash
node e2e.mjs        # 33/33
```

> "AI 写的茶歇系统，33 条端到端全过 —— 包括 18 项论文属性往返、权限 403、推荐排序。
> 而它自己在生成时报出过 1 个没实现的端点、1 次服务起不来。
> **差别不在于 AI 会不会写，而在于有没有东西替它验收。**"

- `cb-6-gates.txt`：锚点轨迹
- `cb-6-tests.txt`：22/22
- `cb-6-e2e.txt`：33/33

> "这些是刚刚在开发机上跑出来的原始输出，文件都在仓库里。
> 现场这台机器如果装的是旧版 Node，我们不为演示去改环境 —— 那反而证明了这套东西的价值：
> **它的结论不依赖现场环境。**"

（这句话本身就是一个论点：可复现性。）
