# AgentForge 赛道 B 材料 · 索引与核心叙事

> 用途：比赛现场 5–8 分钟陈述 + 答辩。这份索引给出**统一叙事**，其余 6 份材料是它的展开。
> 写作原则：所有数字标注 `[实测]`（来自本仓库真实运行/测试）或 `[设计]`（来自代码结构但未经运行验证）。
> **不写无法验证的形容词。**

---

## 一句话

**AgentForge 是一个多角色 AI 研发引擎：它把"让 AI 写一个完整应用"拆成 5 个角色、8 个阶段，
并在每一道关口用 11 条确定性锚点做机械验收 —— LLM 负责产出，但永远不是最终裁判。**

## 30 秒版本（如果只有半分钟）

> 大模型能写代码，但"让它独立做完一个能跑的应用"目前会失败，而且失败得很**隐蔽**：
> 代码能编译、接口路径都在、报告说"已完成"，但一跑测试全是 501 ——
> 因为业务模块写了却从来没人调用。
>
> AgentForge 做的事是：**把"看起来做完了"和"真的能跑"用机械检查分开**。
> 我们跑了 4 轮真实生成，最后定位到的根因不是模型能力，而是
> **系统只验收产出、从不验收输入**——角色在看不到契约和彼此代码的情况下在盲写。
> 修完之后，同一类缺陷从"永远发现不了"变成"第一道关口就报警"。

## 核心叙事（三段，答辩时按这个顺序讲）

### ① 问题：多 Agent 系统的失败是**结构性**的，不是能力性的

三轮真实运行的对照数据 `[实测]`：

| 轮次 | 调用 | token | 产出 | 结果 |
|---|---|---|---|---|
| cb-1 | 13 次 | 550,811 | 后端 4 模块 | 13 个契约端点未实现，0 个测试文件 |
| cb-2 | 30 次 | 1,130,262 | 18 模块 / 4,443 行 | 39 条测试 **26 条失败**（12 个受保护路由一律 501），A7 却报"全部端点已实现" |
| cb-3 | 21 次 | 714,181 | 8 模块 | CONTRACTING 连挂两轮后**带债通过**，BUILDING 里 backend 归因 17 条 |

**同一个病，三轮都没治好**。而每一轮的"失败报告"都把责任指向模型写得差。

### ② 诊断：我们挖到了三层根因，每层都被数据钉住

**第一层 · 判定层**：A7 用子串匹配判"端点已实现"—— 路由表里写着路径就算通过。
真实代码是鉴权后直接 `sendJson(res, 501, ...)`，业务模块一次都没被调用。
→ 新增两条**可达性**检查：`endpoint-stub`（代码里明写"not implemented"）、
`unwired-handler`（导出的请求处理器全项目无调用点/注册点）。

**第二层 · 信息层**（这才是根因）：24,000 字符的上下文预算被"需求 + PRD + 任务图"
三件散文吃掉 **95%**，于是**契约、全部代码模块、全部测试报告一件都进不去** `[实测]`。
后端在看不到契约的情况下写接口，在不知道别人导出了什么的情况下写分发逻辑，
在看不到"哪条测试挂了"的情况下修 bug —— 连修 6 轮不收敛。

同一份数据的另一个签名：8 次调用的输入 token **波动 ±42**，
而项目从 0 行长到 4,443 行。输出/输入 = **2.2 : 1**，**72% 的输出 token 花在重写已有工件上**。

**第三层 · 系统层**：11 条锚点全部在验收**产出**，没有一条问
"产出者拿到做这件事所需的输入了吗"。而录制只存 prompt 哈希，不存"注入了什么、丢了什么" ——
所以"角色没看到契约"这件事在系统里**根本不存在**，只能靠事后复算发现。

> 一句话：**一个只验收产出、从不验收输入的系统，必然把"饿着写"的失败全部误诊成"写得差"。**

### ③ 修复：不是"加预算"，而是"改传接口"

诊断之后的第一个念头是把预算提到 60 万字符、让全部语料一次性进上下文。
**这个方案被否掉了**，理由很硬：AgentForge 的初衷就是**把复杂任务切小、降低单个模型的上下文压力**，
并规定**模型之间只传接口**。堆大上下文等于把多角色系统退化成单一大上下文，切分就白做了。

最终做法是**两条一起**：

1. **预算分配**：按类型的"先到先得" → **五层配额**
   （规格 → 执行事实 → 模块接口 → 代码全文 → 需求计划）。
   契约、测试报告、模块签名**保证送达**，代码全文降级为"尽力而为"。
2. **代码层传接口而不是传实现**：新增**模块接口卡**（`modulecard.ts`），
   只抽取导出签名。11 个模块的全部签名 ≈ **5 千字符**，而它们的全文是 **20 万字符** —— 差 **40 倍** `[实测]`。

外加两件"让问题可见"的工程：**输入审计入 run 日志**（注入了什么、丢了什么、为什么）、
**上下文超长自动减半重试**（不让一次 400 打死整轮 run）。

## 诚实边界（答辩被问到必须直说）

### ✅ 已经能拿出来的东西

**AgentForge 产出过一个真正能跑的完整系统** `[实测]` 2026-10-24：

| 检查 | 结果 |
|---|---|
| 启动（**连 `node_modules` 都不需要**） | `/health` → `200 {"status":"ok"}` |
| 首页 | 200，29,378 字节 HTML |
| `node run-tests.mjs` | **22 / 22 通过** |
| 33 条真实 HTTP 端到端验收 | **33 / 33 通过** |

产物在 **`demo/coffeebreak/`**（132 KB，零第三方依赖，`start.cmd` 双击即跑）。
覆盖：注册/登录/鉴权、论文 CRUD + **18 项属性全部往返**、评论与父子回复、
好友请求与接受、关注与粉丝、兴趣设置与推荐排序、权限边界（非管理员 403）。

### ⚠️ 必须同时说清的三个"没做到"

1. **没有一次自主跑到 `DELIVERED`。** 成功那一轮（cb-6）在 REVIEW 阶段
   A6 修复通过（readyMs 624）之后，**进程被运行环境回收**，没走到最后结账。
   准确表述：**"产品是好的，只是编排没来得及结账"** —— 不是"一次跑完"。
2. **4 轮并行只成 1 轮，方差很大。** 卡住的两轮（cb-7/cb-8）问题都出在
   CONTRACTING：PM 产出的契约质量不稳定。所以不能说"稳定"，只能说"有一次成了"。
3. **语义层（B1/B3）在成功那一轮是 `SKIPPED`。** 即"需求是否达成"的语义判定
   与"主理人异议"没有真正跑过。`SKIPPED ≠ PASS` 是本项目的硬规矩，
   所以我们不把它算作通过。

### 另外两条边界

- **锚点覆盖的是"可机械判定"的性质**，不是"代码好不好"。它抓得住"端点没实现"、
  "模块没接线"、"契约漂移"、"测试没真跑"，抓不住"这个 UI 丑不丑"。
- **锚点自身也需要被标定**：45 个样本，TP 30 / FN 0 / FP 0 / TN 15 / 严重度不符 0。
  样本量不足以给统计意义上的召回率，所以我们更看重**零误报**这个性质。

- **22 / 22 与 33 / 33**：AI 产出的系统，测试与端到端验收**全绿**（`demo/coffeebreak/`）
