## 第 2 页 · 痛点：AI 编程的失败是"假绿灯"（60 秒）

**视觉**：一张表，左边"表面指标"全绿，右边"真实结果"全红。

| 表面指标（AI 说） | 真实结果（跑一下） |
|---|---|
| 18 个模块 / 4,443 行 | 12 个端点返回 **501** |
| `tsc --noEmit` **通过** | 39 条测试 **26 条失败** |
| 17 个契约端点"全都实现了" | 业务模块**一次都没被调用** |

**核心一句**：我的系统当时的检查是"端点路径在代码里出现过吗"，
而真实代码是 `sendJson(res, 501, { error: 'not implemented yet' })` ——
**路径当然出现过，在路由表里。**

> [实测] 这是我自己的真实运行（cb-2），不是编的例子。

## 第 3 页 · 挖根因：不是模型不行，是系统在让人"盲写"（75 秒）

**视觉**：一张"输入 token 随项目规模变化"的折线图 —— 一条**完全水平的线**。

```
输入 token
 12k ┤ ● ● ● ● ● ● ● ●          ← 8 次调用，波动 ±42
     │                    /
  0  └──────────────────────────
      0 行              4,443 行   ← 项目规模
```

**三个数字**：

- 24,000 字符的上下文，被"需求 + PRD + 任务图"吃掉 **95%**
- 54 万字符的工件，真正送达模型的只有 **4.2%**
- 输出/输入 = **2.2 : 1**，**72% 的输出 token 花在重写已有工件上**

**核心一句**：它不是在偷懒，它是在**看不见契约、看不见别人的代码、
看不见"哪条测试挂了"** 的情况下，被要求"把活干完"。
**一个只验收产出、从不验收输入的系统，必然把"饿着写"误诊成"写得差"。**

## 第 4 页 · 架构：编排内核零 LLM（60 秒）

**视觉**：分层图（材料 02 的 mermaid 图简化版）。

```
入口 CLI / Web
   ↓
编排层（零 LLM）  状态机 · Gate · 账本 · 机械裁判 · 圆桌 · 逃生
   ↓
验收层（零 LLM）  A1–A8 事实锚 · B1–B3 语义锚（LLM 提议 + 机械核验）
   ↓
角色层             pm / backend / frontend / test / host
   ↓
能力层            LLM Provider · 三层记忆 · 工件库 · 哈希链日志
```

**三个要点**：
1. **编排里没有一次 LLM 调用** —— 判断逻辑不可能被模型带偏
2. **`SKIPPED ≠ PASS`** —— 环境跑不了时如实报"未验证"，绝不偷偷算通过
3. **8 个阶段共用同一个关口** —— 通过标准不可能在各阶段之间漂移

## 第 5 页 · Agent 链路：不直接对话，只传接口（60 秒）

**视觉**：左侧"错误做法"（全文互传，一张密网），右侧"我们的做法"（星型：所有角色只连契约）。

**两个机制**：

1. **读权限矩阵在代码里强制** —— 不是"请求它别看"，是它根本拿不到
2. **代码层只传接口卡**：11 个模块的全部导出签名 = **5 千字符**，
   而它们的全文 = **20 万字符** —— **差 40 倍**

**核心一句**：切分小任务的意义不是"分给多个模型"，而是**让每个模型只面对它真正需要的信息**。
把全部源码堆进一个大上下文，等于把多角色系统退化成单一大上下文 —— 切分就白做了。

## 第 6 页 · 异常处理：四层逃生，保证不死锁（50 秒）

**视觉**：阶梯图。

```
① 打回返工（便宜、确定）        ← 能归因就先打回，一条都归不了因才开会
② 圆桌会议（唯一允许 LLM 协商）  ← 只"归因完全失灵"才触发
③ 升级真人（一次决定）
④ 带债通过（显式记账）          ← 一定有出口
```

**三个防空转机制**：
- 主理人**阻断 3 次后权限自动终止**（否则两个 Agent 能互相否决到世界末日）
- 已开过圆桌 + 硬失败签名未变 → **不再开会**（实测过某阶段连开 6 次）
- 修复无效 → **直接转逃生**，不重复付费

> 真实日志：[CONTRACTING] 工单修复后硬失败签名未变（pm 的修复没有改变任何东西），
> 不再重复重试，转逃生流程 → 带债通过（受影响需求 3 条）

## 第 7 页 · 可观测性：能回答"它到底看到了什么"（50 秒）

**视觉**：一段真实的 run 日志截图（`context` 字段 + run-progress 输出）。

```
上下文：23,177 / 60,000 字符（39%）  注入 3 个·丢弃 0 个
  其中契约摘要 1 个
  未注入：TaskGraph-001(15520·tier-cap)
```

**核心一句**：这一行是这轮改动最重要的产出。
在这一行存在之前，"为什么它老是做不对"**只能靠猜** —— 我们为此花了两小时复算。

**另外两个可复现性抓手**：
- 决策日志**哈希链**（任何一条被改，链就断）
- **锚点靶场**：45 个样本标定检查本身准不准 → **TP 30 / FN 0 / FP 0 / TN 15**

## 第 8 页 · 结论与展望（30 秒 + 演示）

**已经做到的**：
- **一个 AI 写出来、真的能跑的系统**：22 条测试全过、33 条端到端验收全过（`demo/coffeebreak/`）
- 11 条确定性锚点，401 个测试守着"检查本身是对的"；靶场 45 样本零误报
- 一条可复用的方法论：**先让失败可见，再谈减少失败**

**还没做到的（诚实）**：
- 没有一次自主跑到最终交付（成功那轮在最后一道关卡之后进程被环境回收）
- 四轮并行只成一，**方差还大**
- 语义层（B1/B3）在成功那轮是 `SKIPPED` —— 我们不算它通过

**过渡到演示**："下面是它跑出来的真实系统，以及它在生成过程中自己报过的两个问题。"
