# AgentForge

**让 AI 团队开发软件，并且能证明它真的做到了。**

五个 LLM 角色（产品经理 / 前端 / 后端 / 测试 / 主理人）围绕**接口**而不是对话协作，
产出一个真实可运行的项目；一个**不含任何 LLM 的机械裁判**决定它是否通过交付 ——
每一个「通过」都必须能追溯到一个不依赖 LLM 的事实。

```
一句话需求 ──▶ 五角色分工产出工件 ──▶ 机械裁判用真实证据裁决 ──▶ 可运行的代码 + 可核查的结论
```

- **零运行时依赖**，只要 Node ≥ 24，不需要 `npm install`
- **285 个测试全绿**，CI 在干净机器上跑
- 真实 LLM 端到端跑过 **12 轮**，机械检查全绿时需求 **6/6 确认达成**（且逐条独立复核）

## 它解决什么问题

让 LLM 写代码不难，难的是**知道它写的东西到底行不行**。

三个具体问题，每个都有对应的设计：

**① AI 会编造事实，而且编得很像。** 引用了不存在的包、不存在的函数、不存在的文件。
「让 AI 自己检查一遍」解决不了 —— 它编得出理由，也编得出验证过程。

**② 多智能体协作会逐级放大误解。** 角色之间用自然语言传递，每一层都在猜上一层的意思。
「我以为你懂了」在最后变成集成时的全面崩溃。

**③ 对抗性审查者会退化成橡皮图章或滥报者。** 只说「你必须挑错」，模型的最优策略就变成
「产出看起来像问题的东西」；不加约束的阻断权又会让项目永远停不下来。

## 核心机制

### 一、接口即通信：角色之间不对话

跨角色只传递**类型化工件**（JSON Schema 强制）。schema 校验失败就等于通信失败，不给「理解偏差」留空间。

| 角色 | 产出 | 权限边界 |
|---|---|---|
| **PM** | 需求、PRD、任务图、接口契约 | 可发布需求与契约 |
| **前端 / 后端** | 代码模块、测试 | 只读契约，只写自己 scope 的代码 |
| **测试** | 测试套件、测试报告 | 只读全部代码，不参与实现 |
| **主理人** | 锚定异议包 | 只能提异议与限次阻断，**不能写代码、不能改需求** |
| **机械裁判** | 裁决 | **非 LLM**。异议成立与否由确定性规则判定 |

### 二、机械裁判：LLM 永远不是最终裁判

这条不变量是**结构性**的，不是靠纪律：`packages/anchors`（锚点包）里
**根本拿不到 LLM 客户端** —— `AnchorContext` 没有 provider 字段。
LLM 的语义判断只能以「提议」形式注入，由程序核验证据是否存在后给出最终结论。

异议的裁决是一个纯机械函数：证据必须真实存在（引用不存在的文件/越界行号 → 该条判定作废），
falsifier 必须**当场执行**，并且**与已通过的确定性检查矛盾**的断言直接判为假话。

### 三、多层锚点：11 个确定性检查

A 层零 LLM、纯确定性；B 层有 LLM 参与，但每个结论必须锚定到真实证据。

| | 检查什么 |
|---|---|
| **A1–A3** | 依赖包真的存在？导入的符号真的被导出？每条 import 都能解析到真实文件？ |
| **A4–A6** | 真的编译过？真的跑过测试（含通过/失败数）？真的启动服务并发过 HTTP 探针？ |
| **A7** | 实现与冻结契约是否一致 |
| **A8** | **产出有没有改掉测量工具本身** —— 删改 `package.json` 声明的键、替换测试命令、用 `tsconfig.exclude` 缩小类型检查范围 |
| **B1–B3** | 需求逐条达成的判定、覆盖矩阵、对抗审查 —— 全部必须附真实存在的文件与行区间 |

> **A8 值得单独说**，因为它是被真实事故换来的：生成代码附带的 `package.json` 删掉了
> 项目声明的健康检查地址，于是「真起服务、真发 HTTP」那个锚点**静默变成了「跳过」**，
> 而那次运行照常走到了交付。**如果取证方式可以被被验证者改写，
> 「每个 PASS 都能追溯到事实」就只是措辞。**
> 详见 [`docs/02`](docs/02-anchor-protocol.md) §6.7。

### 四、问责账本 + 三层逃生：对抗但不失控

主理人的评分函数是 **precision（找茬精度）而不是数量** —— 说错话比不说话贵一倍，
而「在检查全绿时如实说没有异议」是正确答案、不受惩罚。
累计误报会进观察期（只能建议、不能阻断）；连续干净阶段可以自动恢复话语权。

**任何角色都无法让项目停死**：打回返工 → 圆桌会议 → 真人裁决 → 带债通过。
最后一层是**第三个状态**，不是 PASS —— `TECH_DEBT.md` 里写明搁置了什么，交付状态只会是「带债」。

### 五、人可以定目标，不能定事实

真人建议书优先级最高，但有一条明确的上界：

- 人**可以**决定要什么 —— 目标、取舍、愿意承担什么风险。落点是 `let-it-pass`：
  系统照做，但未解决的问题记为**技术债**，交付状态只会是「带债」，**永远不记为「通过」**。
- 人**不能**决定事实是什么 —— 编译过没过、测试跑没跑、服务起没起。
  这条是结构性的（硬失败分支在任何建议书被读取之前就返回了）。

每一次「试图推翻事实」都会被**明确回绝**，附上那条挡路的事实与诚实的替代方案 ——
而不是静默无效（那会让人以为自己的决定生效了）。

## 和 MetaGPT / ChatDev / AutoGen 有什么不同

| 已有项目的弱点 | AgentForge 的对应设计 |
|---|---|
| 角色间靠自然语言传递，理解偏差逐级累积 | **接口即通信**：只有类型化工件，schema 失败即通信失败 |
| 审查者无问责，容易变橡皮图章或在提示词压力下附和 | **机械裁判 + 问责账本**：异议必须可证伪 + 附真实证据，由确定性程序仲裁 |
| 没有独立的非 LLM 事实裁决者，幻觉在角色间互相「确认」 | **11 个锚点**：A 层全确定性，B 层判定必须引用真实存在的证据否则作废 |
| 要么过早收敛，要么死循环 | **推进保证**：三层逃生，任何角色都无法让项目停死 |
| 对抗性提示词导致审查者滥报 | **目标函数改成 precision**，误报双倍代价，累计误报进观察期 |

## 它已经证明了什么

| 验证 | 结果 |
|---|---|
| **幻觉靶场**（42 样本 = 28 注入 + 14 干净对照） | 检出 **100%** ／ 干净通过 **100%** ／ **0 误报 0 漏报** |
| **P6 自举验证** | 生成一个真实小应用，再用**绕开锚点系统**的独立手段复核：真 tsc / 真测试 / 真启动 / 真 HTTP |
| **真实 LLM 端到端 12 轮** | 机械检查全绿的那 3 轮，**需求 6/6 确认达成**，并逐条独立复核过 |
| **单元 + 集成测试** | **285 个全绿**；多处做过变异测试（把源码改坏一次，确认测试真的会红） |

**关于那 12 轮，有一条结论值得单独强调：**

> 「机械检查通过」与「需求真的达成」是**两个独立的维度** —— 四个格子都真实出现过。
> 所以系统**如实报两轴**，而不是把它们绑成一个标签。
> 那 12 轮里机械全绿的只有 3 轮，而**这 3 轮的需求全部达成** ——
> 也就是说瓶颈在**生成质量**，不在验证能力。

完整数据（逐轮结果、成本明细、失败模式）见 [`docs/11-project-log.md`](docs/11-project-log.md)。

## 它还不能做什么

诚实清单。**这些是未修项，不是「已解决」。**

### 先说清测试规模：做过真实性测试，但样本远不到「能下结论」的量

**已经做的是小样本真实验证，不是全量测试。** 做过的三件事：

| 做过的 | 规模 | 可信度 |
|---|---|---|
| 单元 + 集成测试 | **285 个全绿**，多处做过变异测试（改坏源码确认测试会红） | 高 |
| 幻觉靶场 | **42 样本**（28 注入 + 14 干净对照），0 误报 0 漏报 | 中高（样本是手写的，属于自出题自答） |
| 真实 LLM 端到端 | **12 轮**，逐轮人工审读 + 关键判定逐条独立复核 | 中 |

**全量测试没做，主要卡在成本。** 一轮真实运行约 **29 万 token / 12 分钟**
（12–64 次 LLM 调用，平均 21 次 —— 调用次数波动大，取决于返工与圆桌的次数）。
12 轮合计 **349 万 token**。

而且这 12 轮是**诊断性**的，不是统计性的 —— 每轮基本都在发现一个缺陷，
花完就该修、修完才值得再跑下一轮。**所以它们测的是「哪里有洞」，不是「它在多大范围内可靠」。**

要真正回答后者，需要的是**矩阵式的重复采样**：多种项目类型 × 多种需求规模 × 每格重复若干次
（模型的输出是非确定性的，实测同一条 prompt 连续两次会给出不同判定，
单次结果不能作数 —— 见 [`docs/11 §2.2`](docs/11-project-log.md)）。
粗算 4–6 种项目 × 2–3 次 ≈ 10–18 轮 ≈ **300–500 万 token**。

**这笔钱现在还没花。** 所以下面每条结论的置信区间都很宽。

> 一个让人稍微信心高一点的趋势：几个最烧钱的低效环节已经修掉了
> （REVIEW 阶段 81% 的 LLM 调用原先是被白白丢弃的、重复开圆桌、定向返工），
> 所以**后续每一轮的信息量在变高、成本在变低**。

### 具体还没验证的

- **样本的构成太单一。** 全部 12 轮跑的是**同一种项目**（一个任务看板、2 条需求、纯 Node、
  内存存储、零第三方依赖）。换成需求翻倍、或有真实前端构建的项目会怎样，**还不知道**。
- **主理人一次都没开过火。** 12 轮里阻断尝试 **0 次** —— 问责账本那套规则
  （额度、误报代价、观察期）**从未被真实数据触发过**。它是「设计良好且未经检验」。
- **参数是猜的**：`BLOCK_QUOTA=3`、误报代价 2、观察期阈值 2。而且因为上一条，现在还**没法标定**。
- **需求判定的权威度永远是「近似」。** 能被机械判定的东西早就变成锚点了，剩下的必然是判断题。
  复核过的 6 条判定全部正确，但**复核目前靠人做，没有自动化**。
- **A1 不核实远端 registry**：名字合法、也不像知名包的假包，离线时抓不到（报 WARN 而非 PASS）。
- **没有「可恢复的 run」**：run 走到「升级真人」就终止，不能带着人的答复继续。

## 快速开始

**引擎零运行时依赖** —— 只要 Node ≥ 24，开箱即用。

```bash
git clone https://github.com/liezhuren/agentforge && cd agentforge

node scripts/run-tests.ts                      # 全部测试（285 个，约 40 秒）
node packages/orchestrator/src/cli-e2e.ts      # 端到端闭环演示：四个场景，全离线
node scripts/anchor-benchmark.ts               # 幻觉靶场：42 样本，出 docs/10
node scripts/verify-real-app.ts                # P6 自举：生成真实小应用 + 独立复核
```

### 接你自己的 LLM

`agentforge.config.json` 里**每个角色**可以独立绑定 provider（OpenAI 兼容 / Ollama）与模型：

```jsonc
"roles": {
  "pm":       { "provider": "deepseek", "model": "deepseek-chat",     "temperature": 0.3 },
  "host":     { "provider": "deepseek", "model": "deepseek-reasoner", "temperature": 0.1 },
  "frontend": { "provider": "ollama",   "model": "qwen2.5:14b" },
  "backend":  { "provider": "ollama",   "model": "qwen2.5:14b" },
  "test":     { "provider": "deepseek", "model": "deepseek-chat",     "maxTokens": 8192 }
}
```

组合是有讲究的：**契约质量与找茬质量决定后续一切**，所以 PM 与主理人值得用最强的模型；
前后端代码量大、A 层锚点会兜底，可以用便宜甚至本地的模型。
支持 `${ENV_VAR}` 引用环境变量，不必把 key 写进文件。
首次使用某个模型时会**自动探测**它的结构化输出能力（strict → json-mode → prompt-only 三级降级），
因为「模型能不能可靠地吐 JSON」这件事**不能猜**。详见 [`docs/08`](docs/08-llm-layer.md)。

```bash
# ── 跑一次真实的 ───────────────────────────────────────
$env:DEEPSEEK_API_KEY="<key>"
node scripts/preseed-llm-workspace.ts workspace/demo   # 建一个带真工具链的空工作区
node packages/orchestrator/src/cli-run.ts --name demo --brief "做一个任务看板：可以创建任务、列出全部任务"
node scripts/inspect-run.ts workspace/demo             # 看锚点结论 + 圆桌纪要 + 落盘文件
node scripts/show-verdict.ts workspace/demo            # 看控制台会显示什么（两轴判定）

# ── 控制台 ─────────────────────────────────────────────
cd apps/web && npm install && npm run build && cd ../..
node packages/server/src/cli.ts                        # http://127.0.0.1:7788
```

控制台打开后**先点「离线演示」** —— 四个预设场景（干净项目 / 幻觉+说谎 / 甩锅+和稀泥 / 交叉质询）
不需要任何 API key，几秒钟就能把整套机制看一遍：锚点红绿灯、主理人账本、
真人介入区（首屏可达）、带规则编号的裁决理由、工件浏览器与事件流。

> 控制台是**独立工程**（React + Vite，需要 `npm install`）—— 这是刻意的：
> 引擎保持零依赖是真实优势，不该为了控制台把它牺牲掉。
